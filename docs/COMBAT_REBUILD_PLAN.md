# 戦闘再構築・実装計画書

対象リポジトリ: `chameleonjp-lab/masumen`  
基準ブランチ: `main`  
計画書の位置づけ: 戦闘実装・検査・仕様判断の基準文書  
作成方針: 物語、人物、固有名称、画像、音楽、画面構成を模倣せず、リアルタイムの判断と駆け引きを独自のゲームとして実装する。

## 1. 最終目標

masumenを、6列×3行の盤面で攻撃を避けるだけのゲームから、次の判断が連続するリアルタイム戦闘へ作り直す。

1. 30枚のカードフォルダを事前に組む。
2. フォルダからランダムに提示された最大5枚を、名前または接続コードで選ぶ。
3. 敵の位置、防御、攻撃準備、パネル、障害物を見てカードを使う。
4. 弾道、設置物、近接、地形、属性相性を使い分ける。
5. 敵の攻撃直前にカードを当て、カウンターを取る。
6. 被弾や危険なカードの使用で精神状態を変える。
7. 時間、被弾、カウンター、同時撃破をスコアへ反映する。

ソウルユニゾン、探索、会話、対人対戦、恒久強化、オンラインランキング、課金、広告、アカウント、開放制限は実装しない。カードカタログ50枚は最初から利用できる。

## 2. 採用する戦闘要素

- 盤面は6列×3行。開始時は左3列がプレイヤー陣地、右3列が敵陣地。
- 通常射撃、距離別発射間隔、チャージ射撃、カード攻撃を同じ戦闘時計で処理する。
- カードは30枚フォルダから抽選し、同名・同一接続コード・共通コード`*`で選択をつなぐ。
- 攻撃は直進弾、貫通、多段、幅広波、投擲、近接、踏み込み、追尾、反射、周回、設置、罠、地形変化、自己効果を個別に扱う。
- パネルは通常、亀裂、穴、草、氷、溶岩、毒、聖域を持つ。属性は無、炎、水、電気、木とする。
- 敵の攻撃には待機、移動、準備、カウンター受付、発動、回復の段階を持たせる。
- 完全同期、動揺、激昂、侵食を実装する。ソウルユニゾンは作らない。

## 5. 今回のPRで固定した基盤

今回の最初の作業では、既存のカード効果や敵の種類を一度に置き換えない。`GameWorld`が描画フレームの実時間へ直接依存しないようにし、次を先に固定する。

- `FixedStepClock`が60Hzの更新を担当する。
- 250ミリ秒を超えるフレーム間隔は、追いつき処理をせず破棄する。
- ゲーム内部の時刻は`GameWorld`の経過時間だけを使う。
- 一時停止、カード選択、命中停止中は内部の敵・弾・ゲージを進めない。
- 再戦時に時計、命中停止、チャージ、敵、弾、スコア、経過時間を初期化する。
- ページ非表示、フォーカス喪失、ページ離脱、`pointercancel`でチャージを解除する。
- 乱数は`Random`へ集約し、同じ種から同じ列を再現できるようにする。

## 6. PR3で固定した盤面基盤

- `PanelSystem`が6列×3行、18枚のパネルを所有し、初期所有権を左右3列へ分ける。
- 通常、亀裂、穴、草、氷、溶岩、毒、聖域を個別の地形状態として保持する。
- 亀裂パネルは占有者が離れた時に8秒間の穴となり、その後通常へ戻る。
- 氷への進入は入力方向へ滑り、穴、障害物、占有者、陣地境界で停止する。
- 敵前列1列の一時的な自陣化と、期限切れ時の安全な自陣帰還を共通処理にする。
- `ObjectSystem`が爆弾、地雷、砲台、キューブ、杭、フィールド装置を保持し、陣営ごとに最大6個、寿命、HP、衝突種別、発動条件を管理する。
- 盤面スナップショットを描画側へ渡し、地形は色だけでなく亀裂、穴、草、氷、溶岩、毒、聖域の形状でも判別できるようにする。
- Wave終了と再戦ではパネル、一時地形、所有権、設置物、占有者を初期化する。

## 7. データ構成の目標

最終的には`GameWorld.ts`へ処理を追加し続けず、次の責務へ分ける。

```text
client/src/game/
├── core/       BattleEngine, BattleState, FixedStepClock, Random, EventQueue
├── systems/    Movement, Attack, Projectile, Object, Panel, Status, Counter,
│               Custom, Emotion, Enemy, Score
├── data/       cards, cardCodes, chainTechniques, overloadCards, enemies,
│               encounters, balance
└── render/     ArenaRenderer, EffectRenderer, CardVfxRenderer, AudioManager
```

React側はHUD、カード選択、フォルダ編集、操作、一時停止、結果、練習を分ける。Babylon.js、React、Viteは維持する。

## 8. 検査方針

各PRで次を実行できる状態を作る。

```text
pnpm audit:card-vfx
pnpm audit:combat-data
pnpm audit:encounters
pnpm audit:board-data
pnpm test
pnpm check
pnpm build
```

後続PRでブラウザ検査を追加し、カード、敵、パネル、乱数、同時決着、再戦初期化を個別に検査する。説明・範囲・描写・音は同じカード定義から参照し、手作業の二重管理を増やさない。

## 9. 著作物との区別

現在の「Signal Relay Tactical」、ティールとオーカーの陣地、独自の敵名、独自カード名を維持する。参考作品の人物、名称、画像、画面写真、音声、音楽、台詞、物語、ロゴ、カード枠、対戦方式は含めない。参考作品名は開発資料内の比較対象に限る。
